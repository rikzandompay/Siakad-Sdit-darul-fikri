PENJELASAN MASING-MASING:

- PHP 8.3        : Bahasa pemrograman utama backend. Versi 8.3
                   mendukung fitur modern seperti typed props,
                   fibers, dan readonly classes.

- Laravel 12     : Framework PHP modern dengan arsitektur MVC.
                   Menyediakan routing, ORM (Eloquent), Blade
                   templating, queue, event, dll.

- Tailwind CSS   : Framework CSS utility-first untuk membangun
  v4.0           UI yang modern, konsisten, dan responsif.

- PostgreSQL     : Database relasional yang robust dan handal.
                   Dipilih karena performa tinggi untuk query
                   kompleks.

- Supabase       : Platform cloud yang mengelola server
                   PostgreSQL. Menyediakan connection pooling
                   untuk efisiensi koneksi database.

- Redis          : In-memory data store yang digunakan sebagai
                   cache layer. Mengurangi beban query database
                   hingga 90% untuk data yang sering diakses.

- Docker/Nginx   : Container dan web server untuk deployment
                   yang konsisten di berbagai environment.

SLIDE 5 - ARSITEKTUR SISTEM
================================================================

JUDUL SLIDE: Arsitektur Sistem

DIAGRAM ARSITEKTUR (deskripsikan secara verbal):

  [Browser User]
       |
       v
  [Nginx Web Server]
       |
       v
  [Laravel Application - Pola MVC]
   |-- Routes (web.php)
   |-- Middleware (Auth, IsAdmin, SecurityHeaders)
   |-- Controllers (Request Handler)
   |-- Models (Eloquent ORM)
   |-- Views (Blade Templates)
       |
       +--[Redis Cache]  <-- data yang sering diakses
       |
       v
  [PostgreSQL via Supabase]

PENJELASAN ARSITEKTUR:
  Sistem menggunakan pola arsitektur MVC (Model-View-Controller):
  - Model    : Merepresentasikan tabel database dan relasi antar data
  - View     : Tampilan antarmuka pengguna menggunakan Blade + Tailwind
  - Controller: Menangani logika bisnis dan menghubungkan Model-View

  Optimasi Performa:
  - Redis Cache digunakan untuk menyimpan sementara data yang
    sering diakses seperti daftar siswa, kelas, dan statistik
    dashboard. TTL (Time To Live) disetel 5 menit.
  - Setiap kali data diubah (CRUD), cache terkait langsung
    dihapus (cache invalidation) agar data selalu akurat.

SLIDE 6 - FITUR-FITUR SISTEM (MODUL)
================================================================

JUDUL SLIDE: Fitur-Fitur Sistem

DAFTAR MODUL:

1. AUTENTIKASI & KEAMANAN
   - Login dengan username dan password
   - Proteksi middleware untuk setiap route
   - Multi-role: Admin (Dewi Quraisyinta/sinta) & Guru biasa
   - Admin: akses penuh CRUD semua data
   - Guru: akses read-only + input presensi dan nilai
   - Security Headers Middleware mencegah serangan XSS dll

2. DASHBOARD (Principal Dashboard)
   - Menampilkan total siswa aktif
   - Total kelas yang tersedia
   - Statistik presensi hari ini (Hadir, Sakit, Izin, Alpa)
   - Persentase kehadiran harian
   - Jadwal mengajar guru sepekan
   - Daftar kelas beserta jumlah siswa aktif
   - Semua data di-cache Redis (5 menit) untuk kecepatan

3. DATA SISWA
   - CRUD data siswa (Tambah, Edit, Hapus, Lihat)
   - Data: NIS, NISN, Nama, Tanggal Lahir, Alamat,
     Jenis Kelamin, Kelas, Nama Wali, No HP Wali, Status
   - Status: Aktif, Lulus, Pindah
   - Fitur pencarian (nama / NIS)
   - Filter: Kelas, Jenis Kelamin, Status
   - Paginasi 15 data per halaman
   - Export data ke CSV dan PDF

4. DATA GURU
   - CRUD data guru/pengguna sistem
   - Data: NIP, Nama Lengkap, Jenis Kelamin, Username,
     Email, No HP, Status
   - Status: Aktif, Pensiun, Pindah
   - Jenis Kelamin: L (Laki-laki), P (Perempuan)
   - Filter: Jenis Kelamin, Status
   - Export data ke CSV dan PDF
   - Proteksi: Akun admin tidak bisa dihapus

5. MATA PELAJARAN
   - Kelola daftar mata pelajaran
   - Data: Nama Pelajaran, Kode Pelajaran

6. KELAS
   - Kelola data kelas
   - Data: Nama Kelas, Wali Kelas
   - Relasi ke siswa dan jadwal pelajaran

7. JADWAL PELAJARAN
   - Input jadwal mengajar per kelas
   - Data: Kelas, Mata Pelajaran, Guru, Hari, Jam Mulai-Selesai
   - Tampil di dashboard guru sebagai jadwal sepekan

8. PRESENSI SISWA (Harian)
   - Guru input presensi per kelas per mata pelajaran
   - Status: H (Hadir), S (Sakit), I (Izin), A (Alpa/Tidak hadir)
   - Filter presensi berdasarkan tanggal
   - Auto-select jadwal berdasarkan hari yang dipilih
   - Bisa input keterangan untuk setiap status
   - Fitur Rekap Presensi:
     * Filter per kelas, mata pelajaran, dan periode waktu
     * Periode: Hari ini, Minggu ini, Bulan ini, Semester ini
   - Export Presensi & Rekap ke CSV dan PDF

9. PRESENSI SHOLAT
   - Khusus mencatat ibadah sholat siswa
   - Dua jenis sholat: Dhuha dan Zuhur
   - Ketentuan:
     * Sholat Dhuha: Kelas 1-6 (semua kelas wali kelas)
     * Sholat Zuhur: Kelas 3-6 saja (kelas atas)
   - Guru input presensi berdasarkan kelas yang diampu
   - Status: H (Hadir), S (Sakit), I (Izin), A (Alpa)
   - Rekap presensi sholat per periode
   - Export rekap ke CSV dan PDF

10. NILAI RAPORT
    - Input nilai per siswa, per mata pelajaran, per tahun ajaran
    - Komponen nilai: Nilai Tugas, Nilai UTS, Nilai UAS
    - Nilai Akhir dihitung otomatis oleh sistem
    - Predikat otomatis berdasarkan nilai akhir:
      * A (Sangat Baik): >= 90
      * B (Baik)       : >= 75
      * C (Cukup)      : >= 60
      * D (Perlu Remedial): < 60
    - Statistik nilai kelas: rata-rata, tertinggi, tuntas, remedial
    - Rekap nilai seluruh mapel per siswa per kelas
    - Export nilai & rekap ke CSV dan PDF

11. PENGATURAN SISTEM
    - Manajemen Tahun Ajaran (Nama Semester, Status Aktif)
    - Hanya bisa diakses oleh Admin

SLIDE 9 - IMPLEMENTASI KEAMANAN
================================================================

JUDUL SLIDE: Keamanan Sistem

LAPISAN KEAMANAN:

1. AUTENTIKASI
   - Sistem login menggunakan username + password
   - Password di-hash menggunakan bcrypt (Laravel Hash::make)
   - Session-based authentication

2. MIDDLEWARE IsAdmin
   - Route sensitif (tambah, edit, hapus data master)
     hanya bisa diakses oleh user dengan is_admin = true
   - Guru biasa yang mencoba akses akan diredirect
   - Contoh route yang diproteksi:
     * POST /siswa (tambah siswa)
     * PUT /siswa/{id} (edit siswa)
     * DELETE /siswa/{id} (hapus siswa)
     * Semua CRUD guru, mapel, kelas, jadwal

3. MIDDLEWARE SecurityHeaders
   - Menambahkan HTTP security headers pada setiap response:
     * X-Content-Type-Options: nosniff
     * X-Frame-Options: DENY (anti-clickjacking)
     * X-XSS-Protection: 1; mode=block
     * Referrer-Policy: strict-origin-when-cross-origin

4. CSRF PROTECTION
   - Laravel otomatis memproteksi semua form POST/PUT/DELETE
   - Token CSRF disisipkan di setiap form

5. VALIDASI INPUT
   - Semua input pengguna divalidasi di sisi server
   - Mencegah SQL Injection melalui Eloquent ORM
   - Validasi format email, panjang karakter, tipe data, dll

6. PROTEKSI AKUN ADMIN
   - Akun admin (sinta) tidak dapat dihapus oleh siapapun
   - Sistem memeriksa isAdmin() sebelum proses delete

SLIDE 10 - OPTIMASI PERFORMA
================================================================

JUDUL SLIDE: Optimasi Performa Sistem

MASALAH:
  - Database Supabase (PostgreSQL cloud) memiliki latensi
    sekitar 150-300ms per query karena koneksi jarak jauh.
  - Dashboard membutuhkan banyak query sekaligus.

SOLUSI: REDIS CACHE

Cara Kerja Redis Cache di SisforSinta:
  1. Saat data diminta, sistem pertama cek ke Redis
  2. Jika data ada di cache → langsung kembalikan (cepat!)
  3. Jika tidak ada → ambil dari database → simpan ke Redis
  4. Saat data diubah (CRUD) → cache dihapus (invalidated)

Data yang Di-cache:
  - Total siswa aktif          (TTL: 5 menit)
  - Total kelas                (TTL: 5 menit)
  - Tahun ajaran aktif         (TTL: 5 menit)
  - Statistik presensi harian  (TTL: 1 menit)
  - Jadwal mengajar guru       (TTL: 5 menit)
  - Daftar kelas per guru      (TTL: 5 menit)
  - Daftar siswa per kelas     (TTL: 5 menit)

OPTIMASI DATABASE:
  - Index performa ditambahkan pada kolom yang sering
    digunakan untuk filter dan join:
    * presensi: tanggal, jadwal_id, siswa_id
    * nilai_rapot: tahun_ajaran_id, pelajaran_id, siswa_id
    * presensi_sholat: tanggal, jenis_sholat, kelas_id

OPTIMASI FRONTEND:
  - Vite digunakan untuk bundling CSS & JS
  - Aset dikompresi dan di-minify untuk produksi
  - Tailwind CSS hanya menghasilkan class yang digunakan

      menggunakan Supabase yang berbasis PostgreSQL."

   Q: "Apa bedanya SisforSinta dengan sistem lain?"
   A: "SisforSinta memiliki fitur unik pencatatan ibadah
      sholat (Dhuha & Zuhur) yang disesuaikan khusus untuk
      kebutuhan Sekolah Islam Terpadu."

   Q: "Bagaimana sistem diuji?"
   A: "Pengujian black-box testing untuk fungsional,
      pengujian keamanan untuk role-based access,
      dan pengujian performa dengan Redis cache."

   Q: "Apa itu Redis Cache?"
   A: "Redis adalah database in-memory yang menyimpan
      data sementara di RAM. Data yang sering diakses
      seperti statistik dashboard disimpan di Redis
      selama 5 menit, sehingga tidak perlu query ke
      database PostgreSQL setiap kali. Hasilnya sistem
      menjadi 95% lebih cepat."
